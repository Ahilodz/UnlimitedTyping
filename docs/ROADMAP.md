## M0 — 仓库与设计文档

**目标**：把项目"当成一个正经项目"开场。

**任务**
- [x] 创建 `README.md` / `.gitignore` / `.gitattributes`
- [x] 创建 `docs/DESIGN.md` / `docs/ROADMAP.md` / `docs/GLOSSARY.md` / `docs/GIT.md`
- [ ] GitHub 上创建仓库并完成首次 `push`
- [ ] （可选）创建 GitHub Issue 记录待决问题 Q1–Q6

**验收**：`git log --oneline` 至少有 1 条提交；GitHub 网页能看到全部文件。

## M1 — PC 端最小窗口

**目标**：一个能跑的 Win32 窗口，里面有能顺畅输入中文的多行文本框。

**任务**
- 建立 `src/` 与 CMake 工程骨架
- 主窗口：标题、一个多行 `RICHEDIT`/`EDIT`、一个"开始输入"按钮、一个"停止"按钮
- 处理窗口消息循环、DPI 感知、单实例互斥

**验收**
- `cmake --build` 成功，双击 exe 能启动
- **在文本框里用微软拼音打一段中文，候选框位置正常、能选词、能回删**
- 关闭窗口进程正常退出

**学到**：Win32 消息循环、窗口过程、控件、资源、CMake、DPI。

---

## M2 — Unicode 注入核心

**目标**：点按钮，文本框里的内容被"打"到记事本里。

**任务**
- `IInjector` 接口 + `UnicodeInjector` 实现（`KEYEVENTF_UNICODE`）
- `TextSource`：切分规则（代理对、`\n`、`\t`）
- 基础节奏控制（固定延时）

**验收**
- 记事本中输入 `你好，世界 abc@qq.com`，**完全一致**
- 输入 emoji `😀` 不崩、不乱码
- 输入含换行的多行文本，换行正确

---

## M3 — 会话控制

**目标**：从"能打"升级到"敢用"。

**任务**
- `TypingSession` 状态机（Idle/Typing/Paused/Completed/Aborted）
- 目标窗口校验 + 失焦自动暂停
- `Esc` / 热键中止
- 断点续打（`cursor` 持久化）
- 随机抖动（`delayMinMs`–`delayMaxMs`）
- RAII 修饰键释放守卫

**验收**
- 打 500 字中文不丢字
- 中途 Alt+Tab 切走 → 立即暂停，切回来能继续
- 中途强杀进程 → 修饰键不残留（键盘不"卡死"）
- 中断后续打，不重复不遗漏

---

## M4 — 触发与常驻

**目标**：像正经工具一样常驻、一键唤起。

**任务**
- 全局热键（`WH_KEYBOARD_LL`，带自注入过滤）
- 托盘图标 + 右键菜单（开始/暂停/设置/退出）
- 配置文件读写（热键、速度、后端）
- 单实例 + 开机自启（可选）

**验收**
- 在浏览器里按热键，文本直接打进当前输入框
- 热键可配置，且能检测冲突并提示
- 托盘状态能反映"正在打字 / 已暂停"

---

## M5 — F103 HID 键盘固件

**目标**：板子在系统里表现为一块真键盘。

**任务**
- CubeMX 工程：HSE 8 MHz → PLL 72 MHz → USB 48 MHz
- `USB_DEVICE` + HID 类，单接口，boot protocol 兼容
- 报告描述符（8 字节：修饰键 + 保留 + 6 键码）
- 按钮扫描（消抖）+ LED 指示

**验收（金标准）**
- **进入 BIOS/UEFI 设置界面，用这块板子能移动光标、能打字**
- Device Manager 中出现 `HID Keyboard Device`
- 拔插 20 次不出现"设备描述符请求失败"

---

## M6 — 双向通道与安全阀

**目标**：PC 能可靠驱动板子，且出了事板子会自动收手。

**任务**
- 下行：Output Report 分帧（magic/type/seq/len/payload）
- 上行：Input Report（buttons/lastSeq/queueDepth/errCount）
- FIFO + `dtMs` 计时回放
- 心跳 + 200 ms 看门狗 + 本地急停

**验收**
- PC 下发 10 个键，板子按顺序打出
- 使用中直接拔掉 USB → 板子（若仍供电）或系统不会残留按下状态
- 使用中强杀 PC 进程 → 200 ms 内自动释键
- 伪造坏帧（错误 CRC/顺序）→ PC 能重发并最终成功

---

## M7 — 后端抽象验证

**目标**：证明架构是对的——换后端，引擎一行不改。

**任务**
- 统一 `IInjector` 签名，把 M2 的实现迁进去
- 增加 `KeyCodeInjector`（扫描码后端）
- 配置文件里可切换后端

**验收**
- 同一段 ASCII 文本，切换三个后端都能正确输出
- 引擎层源文件中 `grep` 不到任何后端具体类名

---

## M8 — ASCII 键码编译器

**目标**：让硬件后端能"看懂文本"。

**任务**
- ASCII → HID Usage ID 表
- Shift 组合展开（`@ ! ? : "` 等）
- 大小写处理、CapsLock 状态规避

**验收**
- 硬件后端正确打出 `Hello World! a@b.com (123) ~ #` 
- 关闭 CapsLock、打开 CapsLock 两种情况都正确

---

## M9 — 提权场景验证

**目标**：打通"过 UIPI"这条路。

**任务**
- 后台服务（`SYSTEM`）持有 HID 句柄
- GUI 与服务通信（命名管道）
- 服务侧实现心跳与队列管理

**验收**
- 在管理员权限的 `cmd.exe` 窗口里，用硬件后端打出 ASCII 文本
- 锁屏状态下（若服务已运行）能打出 ASCII 文本

---

## M10 — 硬件整合

**目标**：从面包板走向能拿在手里的东西。

**任务**
- 原理图：USB-C（CC 脚 5.1k 下拉）、ESD 保护、LDO、去耦、晶振布局
- PCB 布局：D+/D- 90 Ω 差分、等长
- 打样（嘉立创）、焊接、调试
- 外壳（3D 打印 / 亚克力）

**验收**：独立板子插电脑即用，外观可交付。

---

## M11 — 可选功能

- 板载兜底宏（`IBoardStorage`，纯 ASCII，用于极端场景）
- 拼音短句兜底（提权窗口打少量中文）
- UI Automation 回读校验（打完核对，不一致自动重打）
- WebView2 美化界面

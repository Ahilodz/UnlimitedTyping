# 术语表

> 遇到看不懂的名词先查这里。查不到就来问——**问蠢问题不扣分，不懂装懂才扣分。**

## Windows 输入相关

| 术语 | 解释 |
|---|---|
| **SendInput** | Win32 提供的"向系统输入队列写键鼠事件"的 API。用户态能用的最强手段。 |
| **UIPI**（用户界面特权隔离） | 内核强制的机制：低权限进程**不能**向高权限窗口发送输入。`SendInput` 会返回 `ERROR_ACCESS_DENIED`。 |
| **安全桌面（Secure Desktop）** | UAC 弹窗、登录界面使用的独立桌面，普通进程被隔离在外，看不到也碰不到。 |
| **VK_PACKET / `KEYEVENTF_UNICODE`** | 绕过键盘布局、直接发送 Unicode 字符的机制。生成的字符走 `WM_CHAR` 而非按键消息。 |
| **虚拟键码（VK）** | Windows 定义的键编号，如 `VK_RETURN`、`VK_TAB`、`0x41`=A。 |
| **扫描码（Scan Code）** | 键盘硬件实际发出的编号。用扫描码注入兼容性更好（很多游戏只认它）。 |
| **`WH_KEYBOARD_LL`** | 全局低级键盘钩子。可在任何程序之前拦截按键，用于实现全局热键。**回调必须极快**，否则会被系统摘掉。 |
| **`dwExtraInfo`** | `INPUT` 结构里的自定义标记字段。**用来区分"这是我注入的键"和"用户真按的键"，防止自己触发自己（死循环）。** |
| **IME**（输入法编辑器） | 把拼音转成汉字的系统组件。中文输入的一切复杂性源头。 |
| **TSF**（Text Services Framework） | Windows 现代输入法框架。语音输入法大多通过它"插入文本"而非模拟按键。 |
| **UI Automation** | Windows 无障碍 API，可读取窗口控件的内容与状态，用于"输入后回读校验"。 |
| **前台窗口** | 当前接收键盘输入的窗口。`GetForegroundWindow()` 获取。 |
| **DPI 感知** | 程序声明自己如何处理高 DPI 缩放。不声明的话坐标和字体都会错。 |
| **`WM_CHAR` / `WM_KEYDOWN`** | 两种消息：前者是"一个字符"，后者是"一个键被按下"。注入方式不同，产生的消息也不同。 |

## USB / HID 相关

| 术语 | 解释 |
|---|---|
| **HID**（Human Interface Device） | USB 定义的人机接口设备类，键盘鼠标都属于它。**系统内置驱动，无需自写驱动。** |
| **报告描述符（Report Descriptor）** | 一段二进制数据，向主机声明"我这个设备有什么数据、什么格式"。**写错就枚举失败。** |
| **Input Report** | 设备 → 主机 的数据报告（键盘按键、鼠标移动、我们板子的按钮状态）。 |
| **Output Report** | 主机 → 设备 的数据报告（键盘 LED 灯、我们下发给板子的宏）。**这是 PC 驱动板子的通道。** |
| **Feature Report** | 双向的控制类报告，读写配置用。 |
| **Boot Protocol** | 键盘鼠标的"最小兼容协议"。**BIOS/UEFI 只认这个。** 报告必须是 8 字节（键盘）。 |
| **Top-Level Collection（TLC）** | 报告描述符里的一个"逻辑设备"。键盘是一个 TLC，鼠标是另一个。 |
| **HID Usage ID** | HID 规范定义的键编号。`0x04`=A, `0x05`=B, ..., `0x28`=Enter, `0x2C`=Space。 |
| **枚举（Enumeration）** | 插入 USB 后主机与设备交换描述符、分配地址、加载驱动的过程。 |
| **PLL / HSE / HSI** | 时钟源：HSE=外部晶振，HSI=内部 RC。**USB 必须用 HSE 得到精确的 48 MHz**，HSI 会翻车。 |
| **SWD** | STM32 的两线调试接口（`PA13`=SWDIO, `PA14`=SWCLK）。 |
| **DFU** | 通过 USB 直接烧录固件的模式（`BOOT0` 拉高上电）。没有 ST-Link 时的救命方案。 |
| **USB Host / Device** | 主机（电脑）与设备（键盘）。**F103 只有 Device，不能当 Host，所以做不了"键盘中间人"。** |
| **MITM（中间人）** | 把真键盘串进自制板子、拦截后再转发给电脑的技术。需要 USB Host + Device 同时工作。 |

## 项目内部术语

| 术语 | 解释 |
|---|---|
| **后端（Backend）** | 真正执行"输出一个字符/按键"的组件。当前有三个：Unicode / 键码 / HID 硬件。 |
| **引擎（Engine / Core）** | 只负责"决定发什么、什么时候发"的逻辑层，不知道后端怎么实现的。 |
| **触发器（Trigger）** | 让一次打字会话开始的信号来源：热键、托盘、物理按钮。 |
| **会话（Session）** | 从"开始打"到"打完/中止"的完整过程，含游标与状态。 |
| **游标（cursor）** | 当前已经发送到文本的哪个位置。断点续打靠它。 |
| **抖动（Jitter）** | 在固定延时间隔上加随机扰动，模拟真人节奏，避免被判定为机器。 |
| **fail-safe** | 出故障时自动进入安全状态。本项目里指：PC 挂了，板子自动松开所有按键。 |

## Git 相关

| 术语 | 解释 |
|---|---|
| **工作区 / 暂存区 / 仓库** | 你改的文件 / 你挑出来准备提交的文件 / 已提交的历史快照。 |
| **commit** | 一次不可变的快照 + 说明。**提交是"存档点"，不是"上传"。** |
| **remote** | 远程仓库的别名，通常叫 `origin`。`push` 才是上传。 |
| **分支（branch）** | 一条独立的开发线。`main` 永远是能编译的状态。 |
| **tag** | 给某个 commit 起的名字，用来标记版本（`v0.1.0`）。 |
| **`.gitignore`** | 声明"哪些文件不纳入版本管理"。 |
| **`.gitattributes`** | 声明"某类文件怎么处理"（换行符、二进制）。 |

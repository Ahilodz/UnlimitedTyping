# Unlimited Typing — 设计文档

**版本** v0.0.1 · **最后更新** 2026-10-26 · **状态** 草案（随开发迭代）

---

## 1. 一句话定义

把一段文字，逐字符打进任何禁止粘贴的输入框；并可用物理按钮触发。

## 2. 目标（Goals）

| 编号 | 目标 |
|---|---|
| G1 | 在禁用 `paste` 事件的输入框里，可靠地输入长文本 |
| G2 | 完整支持中文（含全角标点），**不使用剪贴板** |
| G3 | 支持全局热键触发与物理按钮触发 |
| G4 | 长文本输入过程可暂停、可中止、可断点续打 |
| G5 | 架构上允许替换输出后端（软件注入 / 硬件 HID 打字） |

## 3. 非目标（Non-Goals）

| 编号 | 不做 | 原因 |
|---|---|---|
| N1 | 绕过游戏反作弊、绕过 EDR | 法律与封号风险 |
| N2 | 兼容任意键盘布局 | 用户环境统一为 QWERTY（中文-美式键盘） |
| N3 | 开发内核驱动 | 微软签名要求 EV 证书（企业资质 + 年费），个人不可行 |
| N4 | 做"键盘中间人"（USB MITM） | F103 无 USB Host；且对本项目目标无帮助 |
| N5 | 在 BIOS/UEFI 中工作 | v1 不做，仅保留接口（见 §13 ADR-002） |

## 4. 用户场景与验收标准

| 编号 | 场景 | 验收标准 |
|---|---|---|
| S1 | 网页表单禁用粘贴，需填入 500 字中文 | 全部正确落地，零丢字、零错字 |
| S2 | 输入中途用户切走窗口 | 自动暂停，不发到其他窗口 |
| S3 | 输入中途需要中断 | `Esc` 或再按热键立即停止 |
| S4 | 中断后需要继续 | 从断点继续，不重复、不遗漏 |
| S5 | 提权程序（管理员权限窗口）里需输入 ASCII | 通过硬件后端完成 |

## 5. 总体架构

```
┌────────────────────────────────────────────────────────────────┐
│  触发层                                                         │
│  全局热键 (WH_KEYBOARD_LL) │ 托盘菜单 │ 板载物理按钮 (经 HID 上报) │
└───────────────────────────────┬────────────────────────────────┘
                                ▼
┌────────────────────────────────────────────────────────────────┐
│  引擎层：UT Core（纯逻辑，不含 Win32 注入细节）                  │
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────────────────┐ │
│  │ TextSource   │→│ TypingSession│→│ IInjector（抽象后端）     │ │
│  │ 文本切分/进度 │ │ 状态机/节奏  │ │ 后端由配置选择            │ │
│  └──────────────┘ └──────────────┘ └──────────────────────────┘ │
│  目标窗口校验 │ 失焦暂停 │ 随机抖动 │ 日志/统计                   │
└───────────────────────────────┬────────────────────────────────┘
                                ▼
┌────────────────────────────────────────────────────────────────┐
│  后端层                                                         │
│  ① UnicodeInjector   ② KeyCodeInjector   ③ HidTypist           │
│     SendInput           SendInput          板子发 HID 键码       │
│     KEYEVENTF_UNICODE   扫描码              需双向通道 + 心跳     │
└────────────────────────────────────────────────────────────────┘
```

**设计铁律**：引擎层不允许 `#include` 任何后端实现头文件，只依赖 `IInjector`。

## 6. 模块划分

| 模块 | 职责 | 依赖 |
|---|---|---|
| `TextSource` | 把文本切分为"可发送单元"（UTF-16 码元 / 换行 / 代理对），维护游标 | 无 |
| `TypingSession` | 状态机、节奏控制、暂停/续打、异常中止 | `TextSource`, `IInjector` |
| `TargetGuard` | 校验前台窗口是否仍是启动时的目标窗口 | Win32 |
| `HotkeyManager` | 全局热键注册/分发 | Win32 |
| `TrayIcon` | 托盘图标与菜单 | Win32 |
| `IInjector` | 后端抽象接口 | 无 |
| `UnicodeInjector` | `SendInput` + `KEYEVENTF_UNICODE` | Win32 |
| `KeyCodeInjector` | `SendInput` + 扫描码（兼容老程序） | Win32 |
| `HidTypist` | 通过板子发 HID 键码 | 板子协议 |
| `TextCompiler` | 文本 → HID 键码事件流（仅 ASCII） | 键码表 |
| `Config` | 读写配置（速度、后端、热键等） | 无 |
| `Logger` | 分级日志、崩溃记录 | 无 |

## 7. 数据模型

### 7.1 打字会话（PC 侧）

```cpp
struct TypingSession {
    std::wstring text;        // 待输入文本（UTF-16，Windows 原生）
    size_t       cursor;      // 已发送的码元下标（断点续打靠它）
    HWND         target;      // 启动时的前台窗口
    int          delayMinMs;  // 字符间隔下限（默认 8）
    int          delayMaxMs;  // 字符间隔上限（默认 20，随机抖动）
    bool         stopOnFocusLoss;
};
```

### 7.2 HID 按键事件（硬件侧）

```cpp
// 4 字节，一次 HID Output Report 最多装 15 个（4×15=60，留 4 字节帧头）
struct KeyEvent {
    uint16_t dtMs;    // 相对【上一个事件】的延时 —— 不用绝对时间戳，免疫时钟漂移
    uint8_t  key;     // HID Usage ID（0x04=A ... 0x29=0，见 HID Usage Tables）
    uint8_t  flags;   // bit0 按下; bit1 LShift; bit2 LCtrl; bit3 LAlt
};
```

### 7.3 可发送单元切分规则

| 输入 | 处理 |
|---|---|
| 普通 BMP 字符 | 一个单元，`wScan = 码元` |
| 代理对（emoji 等） | **两个单元**，连续发送（`KEYEVENTF_UNICODE` 按 UTF-16 码元发） |
| `\n` | 映射为 `VK_RETURN`（不是字符） |
| `\t` | 映射为 `VK_TAB` |
| `\r\n` | 归一化为单个 `VK_RETURN` |

## 9. 打字会话状态机

```
        ┌──────┐  Start   ┌──────────┐  每个字符   ┌────────┐
        │ Idle │─────────▶│ Typing   │────────────▶│ Typing │
        └──────┘          └────┬─────┘  (循环)     └────┬───┘
             ▲                 │                        │
             │        Esc/热键 │  目标失焦/出错          │ 文本耗尽
             │                 ▼                        ▼
             │            ┌──────────┐            ┌──────────┐
             └────────────│ Paused   │──Resume───▶│ Completed│
                          └────┬─────┘            └──────────┘
                               │ Abort
                               ▼
                          ┌──────────┐
                          │ Aborted  │
                          └──────────┘
```

**必须实现的不变量**：

1. 任何退出路径都必须"释放所有已按下的修饰键"（RAII guard）。
2. `cursor` 只在字符**确认已发送**后前进。
3. 每次进入 `Typing` 前重新校验目标窗口。

## 10. 硬件侧设计

| 项 | 规格 |
|---|---|
| MCU | STM32F103C8T6（Cortex-M3，72 MHz，64 KB Flash / 20 KB RAM） |
| USB | Device 全速 12 Mbps，`PA11=DM / PA12=DP`，**必须 HSE 8 MHz 晶振 + PLL 得 48 MHz** |
| 设备类型 | 单接口 HID 键盘（boot protocol 兼容） |
| 上行通道 | HID Input Report：按钮状态、`lastSeq`、队列水位、错误计数 |
| 下行通道 | HID Output Report（64 B）：分帧下发事件流 |
| 输入 | 1 个触发按钮（`PA0`，内部上拉，低有效）+ 1 个急停按钮 |
| 输出 | 板载 LED `PC13`（低电平点亮）+ 外部状态 LED |
| 调试 | SWD `PA13/PA14`，`BOOT0` 跳线引出 |

### 板载必须保留的两条安全逻辑（不接受"板子只做输出"的例外）

1. **心跳看门狗**：连续 200 ms 未收到 PC 心跳 → 停止发送并释放所有按键。
2. **本地急停**：急停按钮不经 PC，直接在固件内生效。

理由：PC 进程崩溃时若按键仍处于按下状态，用户会被锁死在"Ctrl 一直按着"的状态，
只能拔线。这是 fail-safe，与"板子不做业务逻辑"不冲突——它不做**决策**，只做**保护**。

## 11. HID 协议草案

### 11.1 下行（PC → 板子，Output Report，64 字节）

```
[0] magic   0xA5
[1] type    0x01=宏开始  0x02=数据  0x03=宏结束  0x04=中止  0x05=心跳
[2] seq     递增序号（uint8，回绕）
[3] len     payload 字节数
[4..63]     payload：N 个 KeyEvent（4 字节/个）
```

### 11.2 上行（板子 → PC，Input Report）

```
[0] buttons     bit0=触发按钮  bit1=急停按钮
[1] lastSeq     已成功执行的最后一个下行 seq
[2] queueDepth  当前 FIFO 中待播事件数
[3] errCount    累计错误计数
[4] lastError   最近一次错误码
```

### 11.3 PC 侧判错逻辑（"检查是否出错"的责任在 PC）

- `lastSeq` 停滞超过 3 帧 → 重发该帧
- `errCount` 增长 → 记录日志；连续增长 → 中止并提示用户
- `queueDepth` 持续为 0 且文本未耗尽 → 补发数据帧

## 12. 风险登记册

| # | 风险 | 影响 | 概率 | 对策 |
|---|---|---|---|---|
| R1 | `VK_PACKET` 被目标控件忽略 | 高 | 中 | 实机自检；失败则提示切换后端 |
| R2 | 发送过快导致丢字 | 中 | 高 | 可调节奏 + 随机抖动 + 失焦暂停 |
| R3 | 中途失焦导致文本串到别的窗口 | **高** | 中 | 前台窗口校验，失焦立即暂停 |
| R4 | 中文输入法处于组合态导致乱码 | 中 | 中 | 预发送 `Esc` 取消组合（可配置） |
| R5 | F103 USB 枚举失败 | 中 | 中 | 查 R10 上拉电阻、换数据线、核验 48 MHz |
| R6 | 杀软误报（模拟输入类软件常见） | 中 | 中 | 不做进程注入、不混淆、尽早做代码签名说明 |
| R7 | 长文本内存/性能 | 低 | 低 | 分段流式发送，不一次性构造整个事件数组 |
| R8 | 被误用为刷单/灌水工具 | 中 | 低 | README 明确边界，配置里不做批量循环 |
| R9 | 用户机器键盘布局非 QWERTY | 中 | 低 | 文档声明支持范围（当前不做适配） |

## 13. 架构决策记录（ADR）

### ADR-001：主力后端选 Unicode 注入，硬件降级为兜底与触发器

- **背景**：用户希望"真实任何软件都能用"，最初设想驱动级方案。
- **决策**：PC 端用 `SendInput` + `KEYEVENTF_UNICODE` 作为主力；硬件 HID 作为兜底与物理触发器。
- **理由**：① 内核驱动需 EV 证书，个人不可行；② 长中文文本只能靠字符级注入，拼音模拟不现实；
  ③ 核心场景（网页表单禁粘贴）中目标进程与 UT 同权限，UIPI 不构成障碍。
- **代价**：无法在提权窗口与安全桌面输入中文（只能 ASCII）。

### ADR-002：板子只做输出，但保留心跳看门狗与本地急停

- **决策**：业务逻辑全部在 PC；板子仅回放事件流。
- **例外**：心跳看门狗、本地急停必须留在固件，属 fail-safe 而非业务逻辑。
- **遗留**：BIOS 场景保留 `IBoardStorage` 接口，当前不实现（仅 TODO 占位）。

### ADR-003：换行符用 `.gitattributes` + `core.autocrlf=false`

- **理由**：`core.autocrlf=true` 与 `.gitattributes` 的 `eol` 规则会互相干扰并产生大量警告；
  统一由 `.gitattributes` 声明，仓库内一律 LF，Windows 工程文件强制 CRLF。

### ADR-004：v0 界面用 Win32 原生控件

- **背景**：界面必须能顺畅输入中文（IME 支持是第一优先级）。
- **决策**：v0 用原生 `EDIT`/`RICHEDIT` 多行文本框；ImGui 因 IME 支持需额外处理而降级；
  WebView2 作为 v1 美化备选；Qt 留待产品化阶段。
- **理由**：原生控件的 IME 支持是系统级免费的，零风险；先验证核心风险，再谈美观。

### ADR-005：宏在 PC 端"编译"成事件流，板子只回放

- **理由**：文本解析、键码映射、布局换算既复杂又易错，放在 PC 上可调试、可单测；
  板子只做"按 dtMs 计时并发送"，故障面最小。
